2. NEW CONFIGURATION PARAMETERS


Added 4 new memory-related configuration parameters:

1. max-overall-mem (size_t)
   - Total system memory in kilobytes
   - Default: 32768 KB (32 MB)
   - Purpose: Defines the total available memory pool

2. mem-per-frame (size_t)
   - Memory per frame/page in kilobytes
   - Default: 32 KB
   - Purpose: Determines page/frame size for paging system

3. min-mem-per-proc (size_t)
   - Minimum memory per process in kilobytes
   - Default: 8 KB
   - Purpose: Lower bound for random memory assignment

4. max-mem-per-proc (size_t)
   - Maximum memory per process in kilobytes
   - Default: 8 KB
   - Purpose: Upper bound for random memory assignment

All existing MO1 parameters remain unchanged and functional.


3. NEW MEMORY MANAGER CLASS
═

Location: Lines ~242-450 in Group_9_MO2_OS_Emulator.cpp

Key Data Structures:
--------------------

A. PageFrame struct
   - process_id: Owner of this frame (-1 if free)
   - page_number: Which page is stored here
   - is_allocated: Whether frame is in use
   - last_access: Timestamp for LRU algorithm

B. ProcessMemoryInfo struct
   - memory_required: Total memory needed in KB
   - num_pages: Number of pages required
   - page_table: Maps page# to frame# (-1 = in backing store)
   - pages_in_memory: Count of pages currently in RAM
   - pages_in_backing: Count of pages in backing store

Key Methods:
------------

1. allocate_process(int process_id, size_t memory_kb)
   - Allocates memory for a new process
   - Creates page table
   - Initially places all pages in backing store
   - Returns true if successful

2. deallocate_process(int process_id)
   - Frees all frames owned by process
   - Removes from backing store
   - Cleans up page table
   - Called when process finishes

3. page_in(int process_id, int page_number)
   - Brings a page from backing store into memory
   - Handles LRU eviction if memory is full
   - Updates page table and statistics
   - Returns true if successful

4. evict_page()
   - Implements LRU page replacement
   - Finds least recently accessed page
   - Moves page to backing store
   - Frees frame for reuse
   - Returns frame index

5. get_stats()
   - Returns memory statistics (total, used, free)
   - Used by vmstat command

6. get_process_info()
   - Returns per-process memory details
   - Used by process-smi command

7. get_paging_stats()
   - Returns total pages_in and pages_out counters
   - Tracks paging activity

Thread Safety:
--------------
All methods are protected by std::mutex to ensure thread-safe operations
across multiple CPU cores.

5. SCHEDULER CLASS ENHANCEMENTS


Memory Integration:

1. Constructor Changes:
   - Now accepts std::shared_ptr<MemoryManager> parameter
   - Stores reference to memory manager for lifecycle operations

2. add_process() Enhancement:
   - Assigns random memory requirement (MIN to MAX_MEM_PER_PROC)
   - Calls memory_manager->allocate_process()
   - Process stored in memory_required field
   - Memory allocated before scheduling begins

3. execute_process() Enhancement:
   - Simulates memory access during execution
   - FCFS: Calls page_in() every 50 instructions
   - Round-Robin: Calls page_in() every 10 cycles
   - Calculates page number from instruction/cycle count
   - Deallocates memory when process finishes:
     if (memory_manager) {
         memory_manager->deallocate_process(process->get_id());
     }

4. New Field:
   std::shared_ptr<MemoryManager> memory_manager;
   - Shared pointer to memory management system

5. New Method:
   std::shared_ptr<MemoryManager> get_memory_manager() const;
   - Getter for memory manager (used by commands)

13. KEY IMPLEMENTATION DETAILS


LRU Algorithm:
--------------
- Uses std::chrono for timestamp tracking
- evict_page() scans all frames for oldest last_access
- Updates last_access on every page_in() call
- O(n) complexity where n = number of frames

Memory Lifecycle:
-----------------
1. Process created  allocate_process() called
2. Execution begins  page_in() called periodically
3. Process finishes  deallocate_process() called
4. Memory freed for reuse

Paging Simulation:
------------------
- FCFS: page_in() every 50 instructions
  * Page# = (current_line / 50) % num_pages
- Round-Robin: page_in() every 10 cycles
  * Page# = (cycle_count / 10) % num_pages

Thread Safety:
--------------
- All MemoryManager methods use mutex locks
- Safe for multi-threaded scheduler access
- Prevents race conditions in frame allocation
